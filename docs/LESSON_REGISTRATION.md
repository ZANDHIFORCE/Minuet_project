## 등록 규칙

레슨 시간표는 매주 반복되는 **요일·시작 시각**입니다. 특정 날짜의 수업 기록인 `LessonInfo`와 구분합니다.

| 입력 | 규칙 |
| :--- | :--- |
| `teacherId` | 필수, 양의 정수, 등록된 강사 ID |
| `studentId` | 필수, 양의 정수, 등록된 학생 ID |
| `day` | 필수, 0~6. 월요일=0, 일요일=6 |
| `time` | 필수, 00:00~23:59의 분 단위 시작 시각 |

`12:30`과 0초를 명시한 `12:30:00`은 같은 시각으로 취급하며 중복을 우회할 수 없습니다. 0이 아닌 초·나노초 값은 서비스에서도 거부합니다. 폼 입력은 `HH:mm`입니다.

같은 요일·시작 시각에 다음 중 하나라도 겹치면 등록할 수 없습니다.

- 같은 강사: 학생이 달라도 충돌합니다.
- 같은 학생: 강사가 달라도 충돌합니다.

강사·학생이 모두 다르면 같은 요일·시각에 등록할 수 있습니다. 같은 강사·학생도 요일이나 시작 시각이 다르면 등록할 수 있습니다. **현재 모델에는 수업 길이·종료 시각이 없어 시간 구간의 겹침은 검사하지 않습니다.** 예를 들어 13:00과 13:01은 다른 시작 시각으로 허용됩니다.

## 화면과 HTTP 응답

`GET /LessonSlot/new`에서 등록하고 `GET /LessonSlot/list`에서 결과를 확인합니다.

| POST `/LessonSlot/new` 결과 | 상태 | 화면 동작 |
| :--- | :--- | :--- |
| 등록 성공 | 302 | 목록으로 이동, 성공 안내. 새로고침은 GET 요청 |
| 누락·형식·범위 오류, 없는 강사·학생 | 400 | 입력 폼에 필드별 오류 표시 |
| 강사 또는 학생 중복 | 409 | 입력 폼에 중복 안내 표시 |

오류 시 폼의 바인딩 값과 선택을 유지합니다. 필드 형식상 표현할 수 없는 값은 브라우저 입력 요소에서 비어 보일 수 있습니다. 서버가 반환한 SQL 예외 문자열을 사용자에게 출력하지 않습니다. 예기치 않은 서버·DB 장애는 입력 오류로 숨기지 않습니다.

등록 시 바인딩을 허용하는 필드는 `teacherId`, `studentId`, `day`, `time`뿐입니다. 클라이언트가 `id`를 추가해도 기존 시간표 ID를 덮어쓸 수 없습니다.

## 중복이 동시에 들어올 때

애플리케이션의 사전 조회만으로 중복을 판단하면 두 요청이 모두 통과할 수 있습니다. JDBC 구현은 DB의 두 유일성 제약을 최종 기준으로 사용합니다.

```sql
UNIQUE (teacher_id, lesson_day, lesson_time)
UNIQUE (student_id, lesson_day, lesson_time)
```

등록은 한 INSERT 문이므로 중복 검증과 저장을 DB가 원자적으로 처리합니다. 같은 자원을 동시에 등록하면 한 요청만 저장되고 다른 요청은 충돌로 처리됩니다. UPDATE에도 같은 제약이 적용됩니다. 강사·학생 존재 확인 직후 부모가 삭제되는 경우는 외래키 제약으로 보호하고, 서비스가 다시 확인해 입력 오류로 안내합니다.

메모리 저장소는 한 인스턴스에서 동기화한 검사·저장을 사용합니다. 저장된 객체의 참조를 외부로 넘기지 않아, 조회 객체를 수정하거나 충돌하는 수정을 시도해도 저장 상태가 바뀌지 않습니다. 여러 프로세스 사이의 중복 보장은 기본 JDBC 구현의 DB 제약이 담당합니다. 기존 JSON 파일의 충돌 데이터 정리·마이그레이션은 이번 범위가 아닙니다.
